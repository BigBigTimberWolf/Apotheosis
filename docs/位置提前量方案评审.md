# 历史方案：误差积累与背景辅助变向判断

2026-10-03 当前实现以《控制层调参手册.md》顶部说明为准：不再运行背景辅助；FF 去掉末端滤波，支持按参数档标定 X/Y 鼠标换算与响应延迟；跟随补偿的保护直接读取实际 PID 限幅状态。下面保留原方案记录。

更新：2026-10-02。用户明确区分目标变向与准星越过瞄点：前者确认后立即清空旧提前量，后者保留并逐步调整。继续取消固定鼠标换算比例。基础 PID 对照的是指定会话中的 GenshinImpact.sp.exe 逆向；它与 AM 的找色、扳机来源分开。

## 控制路径

原瞄点减去同帧准星得到原始误差。跟随补偿按原始误差进行平滑积分，再把偏移加到原瞄点，交给原 PID。普通积分增益、追近时减缓积累、输出平滑、半画面幅度上限和输出饱和保护保留。

跟随补偿本身不读取成功鼠标运动事件，也不使用鼠标计数到像素的固定换算。基础 PIDF 已按用户要求恢复二次移植版；其独立 FF 速度估计重新读取成功发送事件并使用原 0.91 换算。背景运动只参与跟随补偿的变向判断，不进入 FF。

## 反向规则

原始误差变号仅重启持续性判断，不直接清空积累值或平滑偏移。持续反向误差仍可逐步收回过量补偿。

同一推理画面生成最长边 160 的灰度小图，GPU 路径只回传小图。排除所有检测框及中心准星区域，最多 48 个分散背景特征进行双向光流验证与一致性筛选。通过的背景位移换回原图像素，与原始检测中心位移相减。X/Y 分别至少两个连续有效区间方向一致、累计位移超过误差门限后确认方向变化；确认当帧清空该轴积累值和平滑残留。两轴独立。

背景结果包含时间戳、连续段编号和累计位移，支持控制线程跳过中间推理帧。背景不足、遮挡、时间回退、超过 200ms 间隔、换目标或丢失目标时不沿用旧变向证据。背景未知时维持误差逐步调节，不凭画面速度变号硬清空。至少两个有效区间确认意味着存在确认延迟，不是物理变向第一帧保证识别。

## FF

2026-10-02 最终按用户要求恢复二次移植版基础 PIDF：检测框画面速度加成功发送事件的 0.91 换算，经过速度滤波、门控与双记录关联，再乘 FF 系数。

FF 不消费准星与瞄点误差的变化率。跟随补偿仍只按误差学习，关闭跟随补偿不会关闭速度 FF。固定 0.91 是二次移植版的经验换算，不是设备实测标定。

保留既有 FF 配置键；界面与局域网页中基础 Ki、FF 的范围均为 0..10，超出值在运行时夹到 10。积分上限等于 Ki；准星找色热键开启时保留反向旧积分，关闭时先清旧积分再积本帧。Ki 数值变化清对应轴积分；KpX 或分段设置变化跳过一次输出。默认、第二套、开镜独立参数共用这些规则。

## 诊断与边界

新预览显示 Error rate(px/s)、ERR-LEARN / ERR-HOLD / ERR-REDUCE / ERR-RESET / OFF。这些是跟随补偿诊断，不是 FF 输入。历史状态编号保留；当前 FF 使用跟踪速度，误差变化率仅用于诊断。

背景辅助是局部平移估计，不是真实世界速度测量；景深差异、复杂镜头旋转、未识别的大面积前景或固定 HUD 仍可能造成误差。静止目标尚未拉到时仍可积累补偿，不能承诺大补偿参数不会过冲，也不能消除采集卡内部延迟。

验证覆盖越过瞄点保留、确认变向当帧清空、两轴隔离、重复图像、时间异常、饱和、不同图像间隔、背景平移与前景排除、纹理不足、切场景、跳帧和 CPU/GPU 缩图一致性；速度 FF 与准星误差变化分离；报告 513 的三帧整数结果、Ki 增减与报告 121 的配置状态规则。耗时测试是本机合成画面，实机跟随手感和误判率需要实际使用验证。
