# 宏编排

入口：控制 → 宏编排。每条规则由触发事件、执行条件、动作顺序和规则锁组成，保存到当前方案。旧宏的动作编号与四种执行模式保持兼容，程序仍名为 Apotheosis。

## 页面布局

左侧是宏方案列表（名称、绿点表示已启用、副标题写明“热键 · F1”或“事件 · 失去检测目标”），下方可新建、复制、删除。右侧编辑选中的宏，从上到下是：

- **这条宏会做什么**：一句话白话摘要，随编辑实时更新，例如“按下热键「F1」时，且存在目标，则依次执行：等待 50 毫秒；然后点按键盘「U」，保持 20 毫秒后松开。”
- **① 触发器**：名称与启用；触发方式二选一——“热键”（触发键 + 按下 / 松开 / 按住 / 单击 / 双击 / 三击 / 长按 / 短按 / 按键序列）或“运行时事件”（获得 / 失去目标、自瞄 / 扳机开始与停止等，更多事件排在分隔线下）；执行方式（按一次执行一轮、按住循环、切换循环、逐步执行）、循环间隔与冷却；屏蔽触发键。
- **② 执行条件**：全部满足才启动。一行一个条件（检查什么 + 比较 + 值），用“＋ 添加条件”添加，✕ 删除；还保留旧的“只在检测到目标时运行”限制（类别、框高）。
- **③ 动作时间线**：编号步骤，每一步直接在行内修改，↑ ↓ 调整顺序，⧉ 复制，✕ 删除；底部“＋ 等待 / 键盘 / 鼠标 / 移动”快速添加，“更多动作”里是循环、分支、变量、瞄准等其余动作，它们的参数会按动作类型自动列在该行下方。
- **运行一次**，以及折叠的 **高级规则与调试**：条件组（AND / OR / NOT 等）、找图 / 找色 / 区域条件、规则锁与调度（优先级、互斥、冷却、限流、取消条件等）、中文说明与调试、模拟运行。

条件行只编辑能被一行完整表达的条件（顶层的单个判断，不带区域）。条件组、嵌套条件、带区域的图像 / 颜色条件会显示为只读，并提供“在高级规则里编辑”，不会被悄悄改写。条件编号显示在每行左侧，流程动作按这个编号引用条件；删除条件时，引用它的动作、父组和额外中断条件会同步修正。

## 先做一个可理解的规则

目标：获得目标时，如果 X1 已经按下，等待 50ms，再按 U 50ms 后松开。

1. 新建宏，启用此宏与页面顶部总开关。
2. 触发器的触发方式选“运行时事件”，事件选“获得检测目标”。事件宏不需要触发键。
3. 执行条件点“＋ 添加条件”→“状态与按键”→“指定按键 / 组合键按下”，按键填 `X1MouseButton`（选“成立”）。
4. 动作时间线点“＋ 等待”，最短和最长都填 50；再点“＋ 键盘”，选 U，按住 50。
5. 页面顶部的摘要会用一句话说明实际触发语义；展开“高级规则与调试”里的“中文说明与调试”可以先模拟运行，再在需要时运行一次。

这个规则只在获得目标的瞬间检查 X1。先出现目标、之后才按 X1，不会补发这次事件。如果想让“目标存在且 X1 按下”就触发，应把事件改为“条件满足”，另加“存在目标”条件。

编辑页在本程序前台时暂停自动触发。手动运行一次会真实发送输入；模拟使用独立变量和规则状态，不发送输入、不振动、不播放声音、不写文件。模拟使用启动时的观察快照，所以等待外界改变的条件可能超时。图像条件需要运行采集 / 推理；数据未就绪会说明原因。

标准键、数字区、F1～F24、修饰键、媒体键可选择；通用 Windows 虚拟键可手填 `VK:0xNN`。媒体键和通用虚拟键输出需要 Windows 原生方式；设备固件没有上报的 Fn 等键无法由软件凭空读取。

默认 F12 全部停止，可修改。停止、修改配置、切换方案、设备重连、退出会中断宏并释放持有的按键。宏正在运行时可使用页面顶部的停止按钮。

## 事件、条件与数据来源

- 键盘和五个鼠标键的按下、松开、按住、单击、双击、三击、长按、短按；组合键 `LeftControl+U`，按键序列 `A>B>C`，滚轮 `WheelUp` / `WheelDown`。
- 手柄使用 XInput 的 0～3 号设备，如 `Pad0:A`、`Pad0:LB`、`Pad0:LT`。摇杆条件文本可填 `Pad0:LX`、`Pad0:RY`，范围 -1～1；扳机轴 LT / RT 为 0～1，按键状态以大于 0.5 判断。
- 目标获得、丢失、首次出现、重新出现、持续存在、切换、锁定 / 解锁，以及进入 / 离开 FOV。锁定事件读取控制器状态；检测目标出现不等于控制器已经锁定。
- 自瞄、扳机、准星找色、模板找图、OCR 的开始 / 命中及停止 / 丢失。
- 数值变化、计时器、冷却、规则启用 / 禁用、配置切换、窗口焦点、窗口 / 进程出现及识别分辨率变化。数值变化填指标 ID，例如 `target.count`、`target.class`、`target.confidence`、`target.speed`、`target.visible`；变量写 `variable:名称`。

目标条件包括数量、类别、置信度、最大 / 最小 / 平均宽高、面积、宽高比、位置、区域、FOV、屏幕距离、运动方向、速度、ID 和时长。这里的距离、速度是画面中的像素及像素/秒，不代表实际空间距离。目标 ID 用逐帧关联维持，不直接使用检测列表下标。“原选中目标暂时未检出”表示丢失后的 150ms 状态，不能判断物理遮挡原因。

准星找色命中仅使用检测结果携带的本帧有效准星；沿用前三帧位置或回退中心不算新的命中。宏接管自动输出期间，保持接管前的自瞄 / 扳机状态，避免暂停输出本身产生假停止事件；用户松开自瞄键仍会结束对应激活状态。

系统窗口、进程与手柄在后台采样，不在宏动作线程枚举进程。手柄约每 8ms 更新，窗口 / 进程列表约每 250ms 更新。后台找图 / OCR 默认每 200ms 检查一次，可设置 50～5000ms；结果按原画面的时间戳判断过期。

## 组合条件

支持 AND、OR、NOT（所有子项均不满足）、XOR（奇数项满足）、至少 N 项满足及嵌套组。

父组编号 0 表示顶层启动条件；正数表示归属前面的对应条件组。父组 -1 表示仅供分支、等待或中断动作引用，不参与启动判断。动作中的条件编号从 1 开始，0 表示全部启动条件。删除被引用的条件后，相关动作会报错，不能悄悄变成无条件。

支持等于、不等于、大小比较、闭区间和文本包含 / 相同 / 不同。不存在的目标、未完成的识别、缺失模板、未安装 OCR 语言包均属于“未知”；NOT 不会把未知变成满足。

图像条件的区域使用识别分辨率坐标，宽高为 0 时使用整张画面：

| 条件 | 文本 | 数值 |
| --- | --- | --- |
| 模板找图命中 | 模板图片完整路径，支持中文路径 | 阈值 1 表示命中；“上限 / 找图阈值”填 0～1 的相似度要求 |
| 模板相似度 | 模板路径 | 用阈值比较实际相似度 |
| OCR 文本 | 要匹配的文字 | 比较方式选择文本包含或相同 |
| 区域颜色数量 | 十六进制 RRGGBB | 阈值为像素数量；上限为每通道容差 0～255 |
| 多点找色 | `x,y,RRGGBB;x,y,RRGGBB`，坐标相对区域 | 阈值 1；上限为容差 |
| 像素 RGB | 区域 X、Y 指定像素 | 比较十进制 RGB 数值 |
| 图像变化比例 | 可留空 | 前后两次处理画面的平均灰度差 / 255 |

找图 / OCR 事件优先复用本规则配置的图像条件（包含区域和阈值）；事件匹配文本留空时监测这些条件中的任意命中。如果只填事件匹配路径而没有对应条件，模板默认以 0.9 相似度判断。

模板相似度采用归一化平方差的反值。OCR 调用 Windows 已安装语言包；缺少语言包会显示实际错误，不返回虚构的识别结果。

## 动作与流程

鼠标相对移动、五键按下 / 松开 / 点击、滚轮；键盘单键或组合键按下 / 松开 / 点按；固定 / 随机等待；固定次数循环、条件循环、遍历目标、嵌套循环、跳出和继续；if / else、按变量分支、条件跳转、等待条件超时、条件重试循环、并行分支和调用其他宏。

每个循环、分支、并行块都需要对应结束动作。编译器检查配对及条件引用，最多嵌套 16 层；宏调用最多 8 层并拒绝递归。并行分支从下一次调度开始，父宏在结束处等待子流程结束，父宏取消会一起取消子流程。总并发流程最多 32 个，每轮为每个流程执行至多 8 个立即动作，防止无延迟循环卡住输入线程。

变量支持赋值、加减、乘除、取最小 / 最大；除零与非有限结果会报错。重试循环会执行循环体并检查成功条件，达到次数上限时报错。暂停规则会释放其持有的输入；恢复后从下一步骤继续，不重新按下暂停前的键。

平滑 / 曲线移动使用相对设备计数，按时长分段输出；曲线额外设置垂直弯曲量。绝对移动使用本机虚拟桌面坐标，需要 Windows 原生输出。文本输入同样需要 Windows 原生输出；硬件上用单键 / 组合键动作。

“移动到目标 / 预测点”是根据当前目标、偏移和准星计算的一次设备位移，需要填写每像素对应的设备计数；不使用固定 0.91。预测点另设提前毫秒数。

选择类别、选择优先级、锁定 / 解锁 / 切换 / 清除目标、瞄准部位、额外预测、平滑系数、速度上限已接到控制器。这些覆盖只保存在运行期，全部停止或切换配置后清除；普通宏结束后继续生效，直到后续动作修改或全部停止。部位坐标以框左上角为 0%，右下角为 100%；清除目标使下一控制帧释放当前目标，后续可重新检测。

声音支持系统提示音或 WAV 文件；手柄振动支持左右电机强度和时长。通知、导入 / 导出 INI、切换方案交给界面线程执行，本流程等待操作完成后才进入下一步；失败原因显示在状态与日志中。取消会使尚未开始的排队操作失效。导入遇到同名方案会报错，保留已有方案。方案切换会停止当前宏。配置导出内容是 INI；模板、声音等外部文件仍由规则中的路径引用。

## 规则锁与调度

执行期间本规则不能重入。默认与其他宏互斥；两条规则都开启“允许并行”才能同时运行，相同非空互斥组仍不能并行。开启抢占后，只有更高优先级可以中止低优先级规则。相同触发键可以交给多条规则，按优先级和互斥规则决定执行。

目标锁可限制同一目标只启动一次；按键锁等待组合键全部松开再解锁；冷却从成功启动起计算。还支持启动随机延迟、防抖、总次数、时间窗次数、条件失效取消、目标变化取消、松键取消、额外中断条件和超时。

多个宏按住同一个输入时，最后一个持有者释放才发送松键。如果其他宏已按住某键，点按该键会报冲突。发送失败或取消也会尝试释放本宏输入。传输失败时无法保证硬件已经收到松键，会记录未确认释放。

运行期间暂时接管自动瞄准和扳机输出。延时使用截止时间推进，不睡眠阻塞调度线程。鼠标移动结束后重新建立跟踪状态。原有单次、按住循环、按键开关循环、逐步执行仍可使用。

调试页显示条件是否满足、数据缺失原因、最近动作日志、启动 / 完成 / 中断次数和最近耗时。日志最多保留 200 条。配置保存包含条件树、动作全部参数和调度选项，特殊文本编码保存，数值使用完整双精度输出。

## 验证范围

新增自动测试覆盖事件边沿、嵌套循环、变量与分支、并行持键、子流程取消、超时释放、禁用规则启用、模板事件隔离、非法引用与递归；另有配置保存往返、界面交互 / 截图、图像后台识别和控制器覆盖测试。测试不向键鼠硬件发送真实输入，不能替代客户机器上的硬件与实际场景验证。

## 屏蔽热键

- 瞄准设置 → 触发按键 → **屏蔽热键**，每档独立保存，仅当前热键组中的绑定生效。
- 宏编排 → 触发与条件 → **屏蔽触发键**，每个宏独立保存；需要同时开启宏总开关、此宏并添加动作。目标条件未满足时也会屏蔽原始触发键。停止键冲突的绑定不参与宏屏蔽。
- 两处开关默认关闭。只屏蔽物理触发输入，应用仍能识别按住和松开，程序主动发送的宏动作与瞄准输出保持正常。绑定同一按键的任一有效开关开启，该按键便会屏蔽。
- Windows 原生输入使用本机键鼠低级钩子，在记录外部物理状态后拦截事件；应用自身标记的输出放行。按下、重复及松开保持成对；切换配置后请松开再按。Apotheosis 前台及点击其窗口时放行，避免无法编辑设置。
- KMBox Net 使用盒子的逐键 / 逐鼠标按钮屏蔽，同时读取物理监控。与自动急停的 WASD 屏蔽分别维护所有权，互不取消。连接重建与退出时解除本程序持有的屏蔽；正在按住的键通常等松开后应用新配置。物理监控不可用时不启用屏蔽。
- MAKCU 使用 `km.lock_ml/mr/mm/ms1/ms2`，设置前后查询固件状态，未知命令的原样回显不会被视为成功。标准固件需支持这些查询；项目自定义鼠标旧固件需要更新到下面的 HOTKEY 版本。
- MAKCUNEW 通过能力查询识别新鼠标固件，使用对应 ASCII 控制和屏蔽接口；旧二进制固件仍保留原协议。旧固件缺少屏蔽能力时页面提示更新；不会误用整台键盘的定时屏蔽。
- Ferrum 使用标准鼠标按键锁及键盘 `km.mask(hid,state)`，配合 `km.keys(1)` / `Keys(...)` 读取屏蔽前的键盘状态。
- DHZBox Mini 使用 `mask_left/right/middle/side1/side2`，继续从硬件监控读取物理鼠标。协议没有屏蔽确认回包，因此状态显示“命令已下发”，不宣称设备实测成功。
- 所有后端的本机键盘触发都从 Windows 物理监听读取，可拦截本机键盘热键。KMBox Net / Ferrum 另支持接在盒子上的键盘；MAKCU 独立键盘旧固件和 DHZBox Mini 的远端键盘没有接入逐键屏蔽 / 回读，不能用本机钩子替代。未刷写任何硬件。
- 两页均显示全局屏蔽状态，包括等待松键、设备未就绪及不支持。INI 字段为热键档 `block_hotkey`、宏 `block_trigger`。

### MAKCU 自定义鼠标固件

新源码：`firmware/fw_device`；构建产物：`firmware/fw_device/merged_firmware/Left_MAKCM_MCU_MCU_CUSTOM_V1_1_HOTKEY.bin`。

这是鼠标硬件 USB-A 左板的合并镜像，保留原有真实 / 注入状态分离，只在发给被控机时滤掉被屏蔽的物理按钮；上位机仍能读取真实按钮。右板无需因本功能更新，不适用于独立键盘硬件。镜像合并起始地址为 `0x0`。编译完成不等于已经刷入，也不等于已验证硬件运行。

接口参考：[MAKCU 标准 API](https://makcu.com/en/api/)、[Ferrum 鼠标锁](https://ferrumllc.github.io/software_api/km_api/mouse/buttons/lock.html)、[Ferrum 键盘锁](https://ferrumllc.github.io/software_api/km_api/keyboard/keys/lock.html)、[DHZBox Mini 手册](https://www.scribd.com/document/1077423048/Dhzbox-Mini-%E9%80%8F%E4%BC%A0%E9%BC%A0%E6%A0%87%E7%89%88%E6%9C%AC)。
