# 宏编排

入口：控制 → 宏编排，与瞄准设置、准星找色并列。参考用户提供的 `dllmain.cpp` 的动作与触发语义，使用 Qt 和现有设备连接实现，不依赖原 DLL 的 Lua、ImGui、宿主回调。

## 使用

1. 新建宏，填写名称、触发按键，启用此宏和页面顶部总开关。
2. 选择动作并添加，在下面修改选中动作的参数。可上移、下移、复制和删除。
3. 选择单次、按住循环、按键开关循环，或每次按键推进一步。
4. 可要求检测到指定类别；框高比例表示检测框高度占识别画面高度的百分比，不是实际距离。
5. “运行一次”按顺序执行整份动作一次，仍遵守目标条件。本页在前台时暂停热键触发，切回游戏或其他程序后恢复，松开再按触发键即可。切出窗口不会中断已经手动启动的宏。

默认全部停止键为 F12，可修改。修改配置、停用、切换方案、连接重建、推理会话重置或退出程序都会中止宏并尝试释放该宏按住的输入。延时按截止时间推进，不占用线程睡眠。

等待可设最短与最长值，相等为固定延时。鼠标移动单位为设备计数，X 正数向右、Y 正数向下；滚轮正数向上。组合键用“按住 Ctrl → 点按其他键 → 松开 Ctrl”编排。

逐步模式允许按住状态跨步骤保留，到最后一步释放；循环模式每轮结束释放未配对的按住状态，再等待每轮间隔。按住循环需要一次新的按下，目标条件失效停止后需重新按键。无动作的宏、冲突热键和不支持的设备动作会显示原因。

## 设备与执行约定

- 鼠标左／右／中键、移动和滚轮走当前设备；侧键支持 Windows 原生、MAKCU、MAKCUNEW、KMBox Net，DHZBOX_MINI 和 FERRUM 现有驱动尚未提供侧键输出接口。
- 键盘支持 Windows 原生、KMBox Net，或使用项目 KBD 固件的独立 MAKCU 键盘设备。后者使用已有 `CMD_KEY_MASK` 报文，包含修饰键和 6 个普通按键；不会把键盘事件发到鼠标硬件。无需修改本项目现有键盘固件。
- 点按由宏调度器按下并到时松开，可中途停止。正常停止只释放宏拥有的注入状态。断线时设备可能收不到松开报文，页面会提示未确认释放。
- 按键触发可读取本机键盘、已支持的硬件鼠标回读，以及 KMBox Net 键盘回读。现有 MAKCU 键盘连接没有物理键盘回读接口；只接在被控机上的键盘按键不能凭空被识别。
- 同时只执行一个宏，不排队。运行期间接管自动瞄准／扳机输出；勾选屏蔽的热键按下文规则拦截，其余物理输入保持原样。已有自动切枪任务执行时暂不启动宏。宏鼠标移动结束后重新建立跟踪状态，避免把宏移动当作目标速度。
- PID 重置动作清理相应轴的积分、上一误差和小数残余，不修改增益配置。

配置保存在当前方案 INI 的 `[macro_editor]` 和 `[macro.N]` 节。旧 Lua 路径字段不作为新编排引擎的开关。新建或复制的宏默认停用、不绑定按键。

## Windows 原生输入

硬件 → 输入方式 → Windows 原生输入（SendInput）。无需串口、IP 或外接硬件；输入发送到运行 Apotheosis 的电脑。支持相对移动、五个鼠标按钮、滚轮、键盘点按和按住／松开，以及指定热键的屏蔽；不提供自动急停使用的整组方向键屏蔽。选择后立即初始化。

热键监听使用独立消息线程，只维护按键当前状态，不记录输入内容；忽略带有本程序标记的注入事件，避免输出触发自身热键，同时保留远程控制等外部输入。停止和切换后端时释放本后端按住的注入按键。

原生输入是否被目标程序接受受 Windows 权限和目标程序自身输入处理影响；移动还受系统鼠标设置影响。[SendInput 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。

按用户要求仅编译 Release，不运行测试或宏动作。实际行为由用户验证。

## 屏蔽热键

- 瞄准设置 → 触发按键 → **屏蔽热键**，每档独立保存，仅当前热键组中的绑定生效。
- 宏编排 → 触发与条件 → **屏蔽触发键**，每个宏独立保存；需要同时开启宏总开关、此宏并添加动作。目标条件未满足时也会屏蔽原始触发键。停止键冲突的绑定不参与宏屏蔽。
- 两处开关默认关闭。只屏蔽物理触发输入，应用仍能识别按住和松开，程序主动发送的宏动作与瞄准输出保持正常。绑定同一按键的任一有效开关开启，该按键便会屏蔽。
- Windows 原生输入使用本机键鼠低级钩子，在记录外部物理状态后拦截事件；应用自身标记的输出放行。按下、重复及松开保持成对；切换配置后请松开再按。Apotheosis 前台及点击其窗口时放行，避免无法编辑设置。
- KMBox Net 使用盒子的逐键 / 逐鼠标按钮屏蔽，同时读取物理监控。与自动急停的 WASD 屏蔽分别维护所有权，互不取消。连接重建与退出时解除本程序持有的屏蔽；正在按住的键通常等松开后应用新配置。物理监控不可用时不启用屏蔽。
- MAKCU 使用 `km.lock_ml/mr/mm/ms1/ms2`，设置前后查询固件状态，未知命令的原样回显不会被视为成功。标准固件需支持这些查询；项目自定义鼠标旧固件需要更新到下面的 HOTKEY 版本。
- MAKCUNEW 通过能力查询识别新鼠标固件，使用对应 ASCII 控制和屏蔽接口；旧二进制固件仍保留原协议。旧固件缺少屏蔽能力时页面提示更新；不会误用整台键盘的定时屏蔽。
- Ferrum 使用标准鼠标按键锁及键盘 `km.mask(hid,state)`，配合 `km.keys(1)` / `Keys(...)` 读取屏蔽前的键盘状态。
- DHZBox Mini 使用 `mask_left/right/middle/side1/side2`，继续从硬件监控读取物理鼠标。协议没有屏蔽确认回包，因此状态显示“命令已下发”，不宣称设备实测成功。
- 所有后端的本机键盘触发都从 Windows 物理监听读取，可拦截本机键盘热键。KMBox Net / Ferrum 另支持接在盒子上的键盘；MAKCU 独立键盘旧固件和 DHZBox Mini 的远端键盘没有接入逐键屏蔽 / 回读，不能用本机钩子替代。未刷写任何硬件。
- 两页均显示全局屏蔽状态，包括等待松键、设备未就绪及不支持。INI 字段为热键档 `block_hotkey`、宏 `block_trigger`。

### MAKCU 自定义鼠标固件

新源码：`firmware/fw_device`；构建产物：`firmware/fw_device/merged_firmware/Left_MAKCM_MCU_MCU_CUSTOM_V1_1_HOTKEY.bin`。

这是鼠标硬件 USB-A 左板的合并镜像，保留原有真实 / 注入状态分离，只在发给被控机时滤掉被屏蔽的物理按钮；上位机仍能读取真实按钮。右板无需因本功能更新，不适用于独立键盘硬件。镜像合并起始地址为 `0x0`。编译完成不等于已经刷入，也不等于已验证硬件运行。

接口参考：[MAKCU 标准 API](https://makcu.com/en/api/)、[Ferrum 鼠标锁](https://ferrumllc.github.io/software_api/km_api/mouse/buttons/lock.html)、[Ferrum 键盘锁](https://ferrumllc.github.io/software_api/km_api/keyboard/keys/lock.html)、[DHZBox Mini 手册](https://www.scribd.com/document/1077423048/Dhzbox-Mini-%E9%80%8F%E4%BC%A0%E9%BC%A0%E6%A0%87%E7%89%88%E6%9C%AC)。
