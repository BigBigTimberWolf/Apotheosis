# 当前采集卡的硬件裁切可行性（2026-09-26）

## 目标与判定标准

目标是让采集卡在 MJPEG 编码与 USB 传输之前，对 HDMI 输入画面选取任意矩形，例如 1920×1080 输入中的 320×320 区域，并随目标位置改变窗口。主机收到的应是局部区域的 JPEG，而非完整画面的 JPEG，也不是主机解码时只输出 ROI。

成功必须同时验证：

1. 输入信号保持原分辨率和帧率，窗口坐标可改变。
2. USB 收到的 JPEG 尺寸和内容对应选定区域；移动窗口时内容跟着移动。
3. USB 每帧传输字节数与卡端编码耗时实际下降，且端到端延迟没有反向增加。

## 当前设备与实测

- 设备标识：`USB\VID_048D&PID_CA30&MI_00`，友好名称 `KUHAIMI 4K60 Version`，Windows 使用 `usbvideo.sys`。VID 属于 ITE，但尚未确认这块板上的具体芯片型号。
- Microsoft USBView 导出的 UVC 描述符中，Camera Input Terminal 的 `bmControls=00 00 00`；Digital Window (D20) 和 Region of Interest (D21) 均未声明。其中真正涉及画面视野裁切的是 Digital Window，普通 ROI 主要用于相机自动控制。Video Streaming 的 Compression Window Size 控制也未声明；帧描述符没有 320×320 模式。标准 UVC 接口没有可用的可移动裁切窗口。
- 另有厂商 Extension Unit，GUID `{7CA138CF-71F2-4EC5-8D4C-F087741CABAE}`，24 个选择器全部声明。使用 `tools/ks_capture_probe.cpp` 通过 KS 属性直接查询了这些选择器；这个探测工具对 Extension Unit 只发送 GET 与 BASICSUPPORT 请求。
- 选择器 1 返回 4100 字节，首次可见 `SMEDIA02`，第二次内容不同。该项可能是状态化数据通道，不能据此解释为裁切控制；后续在线状态对比已跳过它。
- 选择器 2–24 在空闲、MJPEG 1920×1080@240、MJPEG 1280×720@60 三种状态下的 GET 值完全相同。第 7 项虽包含非零字段，目前无法证明任何字节代表窗口坐标。
- 直接 KS 采集 1920×1080@240 得到 239.2 fps、首帧约 659 KB；1280×720@60 得到 59.9 fps、首帧约 335 KB。两档的实拍帧保留相同的画面四边，720p 是整幅缩小，非中心裁切。两档画面内容与帧率不同，因此 JPEG 字节数只作格式观察，不能直接当作裁切收益。

## 阶段结论

当前固件没有公布标准 UVC 硬件裁切入口。较低 UVC 输出分辨率会由采集卡输出更小的完整画面，却不能选定动态 ROI。24 个私有控制项说明还不能排除隐藏能力，但现有只读证据未识别出裁切命令。仅重写 Windows 内核驱动无法使设备固件具备未实现的编码前裁切；驱动最多调用已有的设备命令。

因此，目前**不能把这张卡的硬件裁切当作可实现功能安排进主程序**。这不是证明硬件物理上绝无可能，而是接口与协议尚无证据支持。

## 下一步科研路径

1. 获取 KUHAIMI 或 ITE 对此型号的 Extension Unit 协议、SDK、固件功能表，明确是否有 source window / crop / scaler input rectangle 命令。不能仅凭同一 VID 推断芯片功能。
2. 若有厂商工具能操作硬件窗口，抓取其 USB 控制传输或 KS 属性请求，核对 GUID、选择器、命令载荷和设备返回。此时才做可恢复的 SET_CUR 实验。
3. 若厂商确认固件无该功能，应转向具有明确 ROI API 的采集硬件或在 HDMI 源端裁切。软件解码 ROI 仍可降低主机解码成本，但不会减少采集卡已传输的完整 JPEG。

## 复现入口

- `build/cuda/Release/ks_capture_probe.exe --xu-live`：只读查询选择器 2–24。
- `build/cuda/Release/ks_capture_probe.exe --stream MJPG 1920 1080 240 3 --async`：直接 KS 采集，不经 MF/DS。源码在 `tools/ks_capture_probe.cpp`。
- `build/diag/usbview_hardware_crop.txt`、`build/diag/xu_idle.out`、`build/diag/xu_during_1080.out`、`build/diag/xu_during_720.out`：本机原始记录。
