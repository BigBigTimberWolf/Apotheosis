## 一、修复的那个"移动量放大好几倍"bug

### 症状
- 鼠标轻微移动，光标飞出去（位移被放大数倍）
- 快速移动时光标卡顿累积

### 根因
`_onReceive()` 里的解码循环遍历 16 个槽位，对**每一个**满足
`bInterfaceClass == HID && protocol ∈ {MOUSE, NONE}` 的槽位都完整解码一次并发送：

```cpp
for (int i = 0; i < 16; i++) {
    if (endpoint_data_list[i].bInterfaceClass == USB_CLASS_HID) {
        if (protocol == MOUSE || protocol == NONE) {
            ...
            onMouseMove(report);      // 每个匹配槽位都发一次
```

而 `onConfig()` 把**同一个接口**的 class/protocol 复制到了**两个**地方：

```cpp
endpoint_data_list[currentInterfaceNumber] = ...;   // ① 按接口号
endpoint_data_list[ep_num]                 = ...;   // ② 按端点号
```

于是同一个鼠标接口至少被匹配 **2 次**（复合 HID 设备更多）→
**一份位移被重复发送 2~4 次 → 光标移动量成倍放大**；
快速移动时重复帧在 5Mbps 链路上堆叠 → **卡顿累积**。

### 修法（4 行）
```cpp
bool mouseReportHandled = false;
for (int i = 0; i < 16 && !mouseReportHandled; i++) {
    ...
    mouseReportHandled = true;     // 本帧已处理，不再重复注入
}
```

| | 大小 |

只差 1 KB，首个差异在 `0x1001c`（app 描述符元数据区）。
**⇒ 工具链、板级配置、分区表都没问题。**

### 板级配置需显式指定
`platformio.ini` **必须**加 `board_dir = boards`：
平台包（`piocore/platforms/espressif32/boards/`）里**没有** `MAKCM.json`，
不加这行 PlatformIO 会静默回退到通用 ESP32-S3 板定义，
于是 `boards/MAKCM.json` 里的 `extra_flags`（USB_MODE / CDC_ON_BOOT / PSRAM）**全部被忽略**。

`boards/MAKCM.json` 的 `extra_flags` 已与 09-10 老版**逐字一致**：
```
-DARDUINO_ESP32S3_DEV
-DARDUINO_USB_MODE=1
-DARDUINO_USB_CDC_ON_BOOT=1
-DBOARD_HAS_PSRAM
```

### 硬件侧已排除
`USB分级诊断` 实测确认：
- `usb_host_install()` ✅ 成功（USB PHY 正常拿到，efuse / PHY 占用怀疑排除）
- `usb_host_client_register()` ✅ 成功
- 设备能被检测到（出现在设备地址列表里）⇒ **C 口、D+/D-、供电、鼠标本身全部正常**

## 三、诊断固件（`fw_host/src/boottest.cpp`）

右板没有独立的串口芯片（没有 CH343），所以用 **LED9 闪码**做免串口诊断。

启用方式：`platformio.ini` 里的 `[env:BOOTTEST]` / `[env:USBSTAGE]`

### BOOTTEST（`-DFW_BOOTTEST=1`）
完全不碰 USB / Serial1，只用 LED 闪灯。
- 先 3 次长闪 → 持续快闪 = **固件、时钟、启动流程、GPIO9 全部正常**
- 仍完全不亮 = 问题在更底层（bootloader / 分区表 / 硬件）

### USBSTAGE（`-DFW_USBSTAGE=1`）
逐级初始化 USB，结果用闪码报告。

**闪码格式（靠"数个数"，不靠分辨长短）**：
```
① 三短闪           ← 一轮开始
   ── 停 1.2 秒 ──
② 闪 S 下          ← 阶段码
   ── 停 1.2 秒 ──
③ 闪 E 下          ← 错误码低 3 位（成功时无此段）
   ── 停 3 秒 ──
```

| 阶段码 | 含义 |
|---|---|
| 3 | 还没枚举到 |
| 4 | 枚举到但 `usb_host_device_open()` 失败 |
| 5 | ✅ 枚举完全成功 |
| 6 | open 成功但取配置描述符失败 |

### 写诊断代码时的三个坑（都踩过）
1. `usb_host_client_register()` 对**异步**客户端（`is_synchronous=false`）
   **强制要求事件回调非空**，否则返回 `ESP_ERR_INVALID_ARG`。
2. **必须运行事件循环**（`usb_host_lib_handle_events` +
   `usb_host_client_handle_events`），否则枚举根本不推进。
3. `usb_host_device_open()` **必须从 `NEW_DEV` 事件回调内部调用** ——
   设备只在事件派发那一刻可认领，在回调外面轮询是打不开的。
4. 回调参数**不要传局部变量地址**（异步解引用 = 野指针），用文件级静态变量。

## 四、新版本（当前工程主目录）为什么不能用

当前 `fw_host/src/` 的新版（含 1000Hz、二进制帧、HID 解析重写等）**不亮灯不移动**。

已发现的确定问题：
1. **鼠标判定挂在了 `descPerIfaceValid[]` 上** ——
   报告描述符没解析成功就**丢弃每一帧报文，且不报任何错**。
   老版只要求 `class==HID && protocol ∈ {MOUSE, NONE}`，没有这个依赖。
2. `suspend_device()` / `resume_device()` 曾把裸 `this` 塞进 `transfer->context`，
   而 `_onReceiveControl` 按 `ControlContext*` 解引用 → 空指针 → 静默返回。
3. `parseHIDReportDescriptor` 里 `09 30 09 31 81 02` 这种
   **X/Y 共用一个 INPUT item** 的写法，`usage` 变量只剩最后一个值（Y），
   导致 X 轴永远解析不出来。
