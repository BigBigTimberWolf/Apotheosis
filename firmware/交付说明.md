# 本轮改动交付说明

## 一、做了什么

三项功能 + 一批缺陷修复。两个固件都编译通过，产物已生成。

| 功能 | 说明 |
|---|---|
| **键鼠自动识别** | 插鼠标或插键盘都能用，不用改配置。插键盘时固件按键盘工作，插鼠标时按鼠标工作。 |
| **键盘透传** | 真实键盘 → 被控机。控制机软件可以**同时**注入键盘信号，两边不打架。 |
| **瞬时屏蔽** | 给控制机软件一个接口，屏蔽真实键鼠输入几十毫秒。屏蔽期间只有软件注入的信号能到被控机。 |

另外补上了**鼠标按键的"真鼠标 + 注入"合并**语义（原来键盘做了、鼠标没做）。

## 二、必须知道的一件事：报文格式克隆做不了

你最初的目标是"被控机看到的信息和我插的鼠标**一模一样**"。这里要如实说清楚：

### 已经做到的（身份层）

被控机看到的这些**已经和真设备一致**：

- VID / PID
- 厂商名 / 产品名 / 序列号
- 设备类别 / 版本号 / 供电参数

### 做不到的（报文格式层）

**HID 报告描述符改不了。** 被控机读到的描述符仍然是本固件内建的标准格式，不是真鼠标的。

我试了四种做法，全部堵死在 Arduino 框架上：

| 思路 | 结果 |
|---|---|
| 自己继承 `USBHIDDevice` 提供自定义描述符 | ❌ 整个设备只有 **1 个** HID 接口。注册多个设备不会多出接口，只是把各自描述符**首尾拼接**成一块整体上报。 |
| 覆盖 `tud_hid_descriptor_report_cb` 直接返回真描述符 | ❌ 链接报 `multiple definition`。框架源文件是**参与编译**的，不是可按需拉取的静态库成员。 |
| 覆盖 `tusb_hid_load_descriptor` 拦截缓冲指针 | ❌ 同上，同一个 `.o` 里的强符号。 |
| 继承 `USBHIDMouse` 重写 `_onGetDescriptor` | ⚠️ 虚函数**能**重写，但**注册长度改不了** —— 它写死在基类构造函数里（`sizeof(编译期常量)`）。而上报缓冲按"各设备注册长度之和"一次 malloc，长度对不上就是堆溢出。重复调 `addDevice` 又会让长度累加两次，布局整体错位。 |

### 这意味着什么

- **能过**：按型号 / VID-PID / 名字做白名单的检测。
- **过不了**：按 HID 报文格式、USB 报文间隔、端点响应特征做的深度指纹。

即便描述符克隆成功，**时序特征**（报文间隔、响应延迟、注入节奏）依然和真鼠标不同。所以这条路的天花板本来就不高。

**我的判断：投入产出不划算，建议不做。** 如果你仍想推进，唯一的路是修改 `.piopkgs` 里的框架源码 —— 但那会让仓库变脏（别人 clone 后编译出来的固件行为不一样）。

代码里保留了完整说明和收数据的基础设施（`receiveRealHidDescriptor` / `cloned::parse`），将来框架若开放，改动量很小。

## 三、这轮修掉的真实缺陷

都是会让功能**实际失效**的问题，不是理论隐患。

### 缺陷 1：键盘帧被静默丢弃（严重）

`fw_device` 的二进制帧探测被 `g_serial1_binary_moves` 门控，而该标志只在协商 `km.movefmt(1)` 后才置位。但 `fw_host` 发键盘帧是**无条件**的 → 未协商时整个 `0x23` 帧被当成 ASCII 文本灌进环缓冲。

**后果**：键盘完全不通，且 `A5`/`5C` 等非文本字节污染命令解析器。

**修复**：探测条件放宽，与位移格式协商解耦。

### 缺陷 2：屏蔽后按键永久卡死（严重）

`maskStart()` **从不设置** `maskHeldStateValid = true` —— 它只在命令处理函数里设置。任何其它调用路径进入屏蔽，`maskStop()` 就**不发释放命令**。

**后果**：被控机上该键永久按下（游戏里人物一直前进 / 一直射击），软重启都救不回来。

**修复**：把状态快照移进 `maskStart()` 内部，覆盖所有调用路径。

### 缺陷 3：屏蔽期间快照被污染（严重）

`onMouseButtons` / `onKeyboard` 在屏蔽窗口内**持续更新** `maskLast*`。

**后果**：用户屏蔽期间松开按键 → 快照变成"已松开" → `maskStop()` 释放**错误的键**，而真正被设备侧认为按下的键**永远不被释放** → 还是卡死。与缺陷 2 症状相同但成因相反。

**修复**：屏蔽期间快照**冻结**，它记录的是"设备侧冻结的认知"，不是真实输入。

### 缺陷 4：屏蔽后按键失灵（中等）

键盘去重缓存用函数内 `static`，屏蔽结束后仍停在进入前的内容。用户若一直按着同一个键，那一帧被当重复帧丢弃 → 设备侧永远收不到 → 松手重按才恢复。

**修复**：缓存改为成员变量，`maskStop()` 里作废（置 `0xFF` 强制下一帧必发）。

### 另外两处

- **屏蔽可被无限延长**：`maskStart()` 允许重入，失控的调用方可以高频重发 `km.mask(2000)` 把设备无限期锁住。已改为已激活时拒绝重新计时。
- **`releaseAllBuiltinKbd()` 调用时序**：会在覆盖 `s_kbd_keys_prev` **之后**被调用，导致释放"新键"而非"旧键"。上一轮已修，本轮该函数随克隆方案一并移除。

## 四、验证方式

不只是"编译通过"，协议和状态机都做了独立验证：

```bash
python _verify_kb_frame.py   # 键盘帧格式：独立重实现收发两端，往返比对
python _verify_mask.py       # 屏蔽状态机：13 项安全属性
```

`_verify_kb_frame.py` 覆盖：普通按键、修饰键、Ctrl+Alt+Del、6 键同按（NKRO）、全松开、仅修饰键、键码含 `0x00`、键码 `0xFF` 边界、CRC 错误必须拒绝、截断帧必须拒绝 —— **全部通过**。

`_verify_mask.py` 覆盖：硬超时必然触发、时长钳制、拒绝重入、屏蔽期间认知冻结、抬键补发、卡键复现、无按键时不发多余帧、状态收敛、正常透传不受影响 —— **13 项全部通过**。

这两个脚本**就是测试本身**，建议保留。

## 六、建议的实测步骤

1. **键鼠自动识别**：分别只插鼠标、只插键盘、两个都插，确认被控机都能正常操作。
2. **键盘透传**：在真键盘上打字，确认被控机出现字符；再让控制机软件注入按键，确认两者**同时**生效不冲突。
3. **屏蔽**：按住某个键，调 `km.mask(50)`，期间真实移动鼠标应无反应、软件注入应有反应；50ms 后确认真实输入恢复，且**没有按键卡住**。
4. **屏蔽期间松开按键**（重点回归）：按下左键 → 调 `km.mask(200)` → 屏蔽期间松开左键 → 等屏蔽结束 → 确认被控机没有按键卡死。这是缺陷 3 的复现场景。
5. **屏蔽后同键复按**（重点回归）：按住 `A` → 屏蔽 → 屏蔽结束后继续按着 `A`，确认 `A` 仍被识别为按下。这是缺陷 4 的复现场景。

## 七、新增接口

| 命令 | 作用 |
|---|---|
| `km.mask(<毫秒>)` | 屏蔽真实键鼠输入，上限 2000ms，默认 50ms |
| `km.maskoff` | 立即解除屏蔽 |
| `km.cloneinfo` | 回报真设备描述符接收情况（诊断用） |
| `km.reenum` | 触发 USB 重枚举（副作用：COM 口断约 1 秒） |
